# fans通知弹窗中心

> 作者：**fanslater** · 包名 `dsh-fans-notify-center` · 当前版本 **0.4.4**

把 DSH 的「会话状态变更」变成**屏幕右下角的常驻通知弹窗**：任意工作区、任意会话出现
「跑完了 / 等你审批 / 等你回答」，都会独立冒出一张卡片；卡片不会自己消失，只有你点 `✕`、
点「全部清除」，或者真的进入那个会话，它才会走。

## 为什么不用系统通知

Windows 的 Toast（`dsh-notify-me` 走的就是这条路）由系统托管，有三个绕不过去的限制：

| 想要 | Toast 的实际情况 |
| --- | --- |
| 一直挂着，直到我处理 | 几秒后自动收进通知中心 |
| 一个会话一张，竖向排列 | 同一应用同时只弹一条，其余排队 |
| 必须我点 X 才关 | 点一下空白/滑动/超时都会没 |

所以本插件不调系统通知，而是自己画一个无边框、置顶、不抢焦点的窗口，锚在 DSH 窗口所在那块屏的右下角。

## 三个效果

1. **一定会弹**：通知源在宿主进程里（`session/event` 的 `turn/end`、`approval/request`、
   `user-questions/request`），不依赖页面是否打开、窗口是否最小化、系统通知权限是否被静音。
2. **必须你处理**：卡片没有任何定时器，唯一的移除路径是 `✕`、全部清除、点击卡片进入会话，
   以及在 DSH 里手动打开该会话（浏览器半会回报「已读」）。
3. **N 条并存**：每条通知一张卡，从下往上堆；超过上限时顶部显示「还有 N 条更早的通知」。
   点掉一张少一张，最后一张消失时窗口自动隐藏。

## 怎么用

- **入口**：`插件 → 已安装 → fans通知弹窗中心`，右侧开关就是这个插件的总开关。
- **配置位置**：点进插件页，配置表单就在**简介下面、组件列表上面**（`plugins.bundle.config`
  槽，key 为包名）。它不在「设置」菜单里，也不在「包含的组件」那一行里。
- **四个按钮**（风格与 fans 系列插件配置页一致）：
  - **保存配置**：把当前表单写进 `%USERPROFILE%\.dsh\profiles\<profile>\notify-center.config.json`
    并立即生效（会重启一次弹窗进程，已显示的卡片不丢）。**没有改动时置灰**，
    表单与已保存配置不一致时才亮起（蓝色主按钮）；
  - **恢复默认**：只把**表单**恢复成默认值，**不落盘**；要点「保存配置」才会真正生效；
  - **测试弹窗**：立刻发 3 张示例卡（待审批 / 待回答 / 已完成各一张），按当前位置和
    透明度渲染，改完偏移/透明度后不用等真实通知就能看效果；
  - **清除测试卡片**：只清掉这些 `test-*` 示例卡，**不影响任何真实通知**。
- **配置只在这里**：本插件不注册任何 DSH 设置页，配置不会出现在「设置」菜单里。
  配置文件落在 `%USERPROFILE%\.dsh\profiles\<profile>\notify-center.config.json`。
- **可配置项**（共 13 项）：

  | 分组 | 项 | 默认值 | 说明 |
  | --- | --- | --- | --- |
  | 总开关 | 启用通知弹窗 | 开 | 关闭后不再产生卡片，已显示的也会清空 |
  | 范围 | 子代理会话也提醒 | 关 | 子代理只是某个主会话的一步，默认不提醒以免刷屏 |
  | 提醒类型 | 回合完成 | 开 | Agent 跑完这一轮回复 |
  | 提醒类型 | 待审批 / 计划确认 | 开 | 工具调用等你批准，或计划等你确认 |
  | 提醒类型 | 等待回答 | 开 | `ask_user_question` 等你选 |
  | 提醒类型 | 出错 / 被中断 | 开 | 本轮报错、被拦截或被中断 |
  | 位置 | 底部避让高度 | 100 | 卡片底边距 DSH 窗口底部的距离（0–400），需大于输入框高度，避开发送按钮区 |
  | 位置 | 右侧偏移 | 8 | 卡片右边缘距 DSH 窗口右缘的距离（0–400），0 就是贴住右缘 |
  | 外观 | 卡片背景不透明度 | 100% | 20%–100%；只调背景底色的透明度，文字/描边保持清晰，悬停时底色加深 |
  | 外观 | 配色 | 跟随系统 | `auto` 跟随 **DSH 页面主题**实时切换（第三方主题包也支持，按页面背景亮度判定；页面没上报过时退回 Windows 系统主题）；`light` / `dark` 固定 |
  | 外观 | 显示在哪块屏 | 跟随 DSH 窗口 | `dsh` 跟随窗口所在屏；`primary` 固定主屏 |
  | 外观 | 卡片宽度 | 360 | 260 – 620 像素 |
  | 外观 | 最多同时显示 | 6 | 1 – 20 条，超出的折叠为「还有 N 条更早的通知」 |

- **位置与避让**：弹窗长期固定在 **DSH 窗口右下角**（不锚屏幕，跟随窗口所在屏），
  底边距窗口底部 `底部避让高度`、右缘距窗口右缘 `右侧偏移`，正好悬在会话输入框上方。
  堆叠高度有**动态折叠**保护：可见卡片数会被压进「输入框上方 ↔ 标题栏下方」的可用高度内，
  放不下就折叠为「还有 N 条更早的通知」——无论怎么配置都不会压到输入框按钮或标题栏。
  早期版本的 `anchor / topOffset / topShift` 配置键已废弃，文件里残留会被自动忽略。

- **通知窗口头部**：左上「N 项待处理」为半透明加粗中字；右上「全部清除」为主色文字按钮
  （蓝色半粗字、无框无底、悬停出现下划线、命中区约 60×24）。头部自身不带底色，保持轻量。

- **隐藏开关**：配置文件里还有一个 `test`（默认 `true`），控制是否保留只用于自检的
  `/test` 路由（往窗口塞示例卡片）。表单里不暴露，一般不用动。

## 结构

```
dsh-fans-notify-center
├── lib/index.js        宿主半：事件监听 + 卡片状态 + 路由 + 拉起窗口 + 配置读写
├── lib/client.js       浏览器半：点卡片→切会话、已读回报、插件页配置表单
├── win/NotifyCenter.cs 置顶窗口（WPF，C# 5）
├── win/build.ps1       用系统自带 csc 编译，无需 SDK
└── win/NotifyCenter.exe  编译产物
```

数据流：

```
宿主事件 ──► 卡片状态 ──GET /__dsh-notify-center/state──► NotifyCenter.exe（每 700ms 轮询）
                                                                │
 浏览器半 ◄──GET /__dsh-notify-center/actions──── 宿主 ◄──POST /action {open|dismiss|clear}──┘
      └── uiWorkspace.openSession(sessionId)
```

窗口进程由宿主 `spawn`，插件卸载/宿主退出时一起结束；窗口异常退出时看门狗（15s）在有卡片
的情况下重新拉起。

## 验证与排查

DSH 桌面端每次启动的监听端口可能不同，下面示例用 `11997`；取当前值的办法是看 `/status`
返回里的 `origin`，或直接换成你地址栏里的端口。

```powershell
# 宿主自检：卡片、窗口进程、配置、浏览器半是否在轮询
Invoke-WebRequest http://127.0.0.1:11997/__dsh-notify-center/status -UseBasicParsing | Select-Object -Expand Content

# 读/写配置（与插件页表单同一套接口）
Invoke-WebRequest http://127.0.0.1:11997/__dsh-notify-center/config -UseBasicParsing

# 塞 3 张示例卡片（只看样式，不产生真实会话）
Invoke-WebRequest http://127.0.0.1:11997/__dsh-notify-center/test -Method POST -Body '{"count":3}' -ContentType 'application/json'

# 窗口进程日志（每次启动重写，超过 512KB 自动截断）
Get-Content "$env:TEMP\dsh-notify-center-window.log" -Tail 30
```

`/status` 里有用的字段：`window`（窗口进程）、`items`（当前卡片）、`queue`（待页面消费的
打开指令）、`config`、`configFile`、`stats.clientPolls`（浏览器半是否活着）。

## 重新编译窗口

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File win\build.ps1
```

用的是 `%WINDIR%\Microsoft.NET\Framework64\v4.0.30319\csc.exe`（.NET Framework 4.8 自带），
所以代码按 **C# 5** 写：不能用 `$"..."`、`?.`、`=>` 表达式体等语法。

## 已知限制

- **仅 Windows**：窗口是 WPF。
- **.NET Framework 要求**：目标运行时为 **4.7.2**（Win10 1803+ / Win11 原生自带，零安装）；
  4.8 / 4.8.1 向下兼容。代码未使用任何 4.7.2 之后的 API，任何 Win10/Win11 机器都不需要
  手动安装 .NET Framework。
- **DSH 退出后没有通知**：通知源在宿主进程里，进程没了就没有事件。
- **插件重载/宿主重启会清空卡片**：卡片状态在内存里，等待中的审批需要重新触发才会再出现
  （审批本身不受影响）。
- **点卡片会把 DSH 窗口提到前台**：这是「点击进入会话」的必要动作，不想被抢焦点就用 `✕`。
- **与 `dsh-notify-me` 的关系**：本插件就是来替代它的，它已从 desktop profile 卸载；本插件的
  事件源、窗口、配置全部自包含，不依赖它的任何代码。
